# 工艺问答技能

## 功能说明

通过配置的知识库 HTTP API 发送用户问题，并将接口返回的回答整理后展示给用户。

## 接口配置

- **请求地址**: `{KNOWLEDGE_BASE_HTTP_URL}`
- **请求路径**: `/api/chat`
- **请求方式**: HTTP POST
- **请求头**: `Content-Type: application/json`
- **请求体**:

```json
{
  "question": "内防护系统装配有哪些内容",
  "keywords": ["内防护"],
  "includeDebug": true
}
```

## 执行步骤

### 第一步：确认问题正文和关键字

从用户消息中提取要提问的内容，填入 `question` 字段。`keywords` 只放问题里的具体对象，例如零件名、工序名、产品型号。不要使用「关键字1」这类占位词，也不要放「整机」「集成」这种过宽的词，它们会把无关工艺卡一并命中。

如果用户只表达了想查询知识库，但没有给出明确问题，应先询问用户要查询的问题正文，不要编造默认问题。

### 第二步：调用工艺问答接口

使用可发送 HTTP POST JSON 请求的工具访问配置地址：

- url：请求地址+请求路径
- body：参考接口json样例

优先使用`python`生成本地脚本执行再执行，脚本参考${SKILL_DIR}\references\query_rag.py
不要将问题拼接到 URL 或 query string 中；必须放在 JSON body 的 `question` 字段里。

### 第三步：响应

成功时返回一个 JSON 对象，不是流式增量。按下面字段处理：

| 字段                 | 用途                                                                   |
| -------------------- | ---------------------------------------------------------------------- |
| `answer`             | 给用户看的结论，放在回复最前面                                         |
| `hitProcesses`       | 命中的工艺卡。每条含 `id`、`drawingNo`（图号）、`name`、`productModel` |
| `context`            | 这些工艺卡下的工序、工步原文，用来核对装入件名称                       |
| `truncated`          | 为 `true` 时说明上下文被截断，要告诉用户结论可能不完整                 |
| `usedVectorFallback` | 为 `true` 时说明没有靠关键字命中，而是退回了向量检索                   |

展示时：

1. 先给出 `answer`。
2. 只保留和问题对象直接相关的 `hitProcesses`，写明名称、图号、产品型号。关键字过宽带出来的其他工艺卡不要当成这条问题的依据。
3. 需要核对工序或装入件时，从对应工艺卡的 `context` 里摘工序、工步，不要改写成另一条工艺的内容。
4. 自制件按工步中的名称核对。标准件、外购件只有在工步原文里同时出现件号和名称时，才算在该工序下有指派。

### 第四步：错误处理

根据 HTTP 状态或工具错误给出清晰说明：

| 状态     | 含义         | 响应方式                                             |
| -------- | ------------ | ---------------------------------------------------- |
| 200      | 请求成功     | 整理并展示完整回答                                   |
| 400/422  | 请求参数错误 | 提示问题正文或 JSON 格式可能不符合接口要求           |
| 500      | 服务端错误   | 提示工艺问答服务处理失败                             |
| 网络错误 | 无法连接     | 提示确认知识库 HTTP URL 配置是否正确、服务是否已启动 |

## 安全要求

- 只访问配置替换后的 `{KNOWLEDGE_BASE_HTTP_URL}` 地址。
- 不要向请求中加入用户未明确提供的敏感信息、凭证或本地文件内容。
- 请求路径必须是 `/api/chat`，不要改成 `/api/qdrant/chat`，也不要加入 `stream` 字段。

## 示例

用户：`内防护系统装配有哪些内容`

请求体：

```json
{
  "question": "内防护系统装配有哪些内容",
  "keywords": ["内防护"],
  "includeDebug": true
}
```

返回后：先展示 `answer`。相关工艺卡写名称、图号和产品型号，例如「7.9机械装配配套工艺卡（整机级）」，图号 `UJ800.02.01.03.02b`，产品型号 `CSS-1020光刻机`。工序和装入件以该卡 `context` 中的工步为准。
